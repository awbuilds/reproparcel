Report privately, reproduce minimally

ReproParcel handles evidence that may be sensitive. Privacy failures, parser escapes and host crashes are treated as security issues, not ordinary bugs.

i

Use GitHub private vulnerability reporting. Do not open a public issue containing a real report, screenshot, credential, customer data or exploitable detail. If the private channel is unavailable, stop and ask the maintainer to enable it before sharing details.

Open a private security advisory

Supported versions

There is no stable release. Security fixes target the current dev source candidate. No backport or response-time SLA is promised.

Scope

In scope

  • Privacy failures, secret leakage, unsafe capture or masking.
  • Parcel parser, viewer or MCP path traversal, decompression bombs or code execution.
  • Lifecycle, cancellation or exception paths that can crash the host.
  • Insecure storage, FileProvider/SAF grants or backup exposure.
  • Dependency or supply-chain issues in shipped artifacts.
  • Read-only MCP tools that expose arbitrary files, writes or execution.

Out of scope

  • Vulnerabilities in a host application's own code or policy.
  • Reports that require a malicious in-process host to bypass its own policy.
  • Denial of service against maintainer infrastructure.
  • Issues in a host application or a forked build.

What to include

Provide a synthetic or minimal reproduction, the affected commit or artifact, the impact, and the smallest evidence needed to reproduce. Do not include real user reports, screenshots, credentials or personal information. The maintainers may ask for a private artifact only after agreeing on a safe channel.

Useful details:

  • Exact command, build variant, API level and device class.
  • The typed outcome or omission reason.
  • Whether the issue reproduces with the release/R8 build.
  • Whether report content, image pixels or metadata are exposed.

Disclosure

Coordinate disclosure with the maintainer. No bounty is offered. Confirmed evidence leaks or SDK-induced host crashes can require disabling the affected feature and shipping a patch before any public detail is published.

Threat model summary

The project treats the following as assets: report text, image pixels, build and device metadata, draft encryption keys, exported files and the host application's stability.

ThreatRequired control
Capturing a protected windowFLAG_SECURE checked before and after capture; omit on any doubt.
Masked content recoverableMasks are destructive on the sanitized bitmap; no hidden original layer is persisted.
Stale capture races a layout changeAttempt token bound to window, policy and layout generation; post-copy re-check.
Secrets in logs or network metadataAllowlisted fields only; no bodies, cookies, headers, query strings or raw URLs.
Draft read after device compromiseAES-256-GCM with an Android Keystore key; no plaintext fallback; backup excluded.
Hostile parcel at importBounded ZIP/JSON/PNG validation before extraction or rendering.
Script execution in the viewerEscaped text, no scripts, restrictive CSP, no external URLs.
Agent tool escapes the import rootReport IDs, not paths; five read-only tools; no write or execute.
Model provider receives evidenceDocumented warning; the project cannot enforce client egress.

The full threat model lives in the repository. Read docs/security/threat-model.md.

Privacy issues are security issues

If you find a path where evidence is captured without a policy, a mask can be undone, plaintext is written when encryption fails, or a parcel is extracted outside its bounds, report it privately through the advisory channel.
