Initialize the runtime

Initialization is explicit and idempotent. Collection stays disabled until the host enables it.

Runtime setupkotlin
val config = ReproParcelConfig(
    enabled = false,
    buildInfo = BuildInfo(
        packageName = BuildConfig.APPLICATION_ID,
        versionName = BuildConfig.VERSION_NAME,
        versionCode = BuildConfig.VERSION_CODE.toLong(),
        variant = BuildConfig.BUILD_TYPE,
        gitCommit = null, // supply a reviewed commit when available
    ),
    capturePolicy = CapturePolicy(
        policyVersion = "app-policy-v1",
        screenshotEnabled = true,
        semanticTextEnabled = false,
        eligibleSurfaces = setOf("checkout_review"),
    ),
)

ReproParcel.initialize(applicationContext, config)
ReproParcel.setEnabled(true)
ReproParcelCompose.showReporter(activity, surfaceId = "checkout_review")
!

Do not enable what you cannot review. Screenshot and semantic collection remain disabled unless the host supplies a reviewed policy. The sample starts with collection disabled and exposes a manual enable control.

Capture policy

FieldMeaning
policyVersionHost-defined policy generation. A mismatch invalidates an in-flight capture.
screenshotEnabledMaster switch for image capture. Defaults off.
semanticTextEnabledMaster switch for explicit semantic evidence. Defaults off.
eligibleSurfacesExplicit allowlist of surface IDs. An unlisted surface is omitted.

An omitted surface is a valid outcome. The reporter still produces a text-only report; do not weaken the policy to force an image.

Evidence adapters

Breadcrumbs

Short, allowlisted navigation or state markers. Unknown or unsafe attributes are dropped before the bounded buffer.

Structured logs

The host submits structured entries. The SDK does not read global logcat and does not capture arbitrary strings by convenience.

OkHttp metadata

The optional reproparcel-okhttp interceptor records method, status, timing and a safe route template. It does not consume or buffer request/response bodies, cookies, authorization headers or query strings.

Semantics

Explicit host-registered descriptors are the v1 baseline. Automatic Compose tree extraction is not shipped until a public-API, minified-release compatibility experiment passes.

Desktop tools

Desktop commandssh
cd desktop
npm ci
npm run build

node dist/cli.js validate report.reproparcel --json
node dist/cli.js inspect report.reproparcel --json
node dist/cli.js render report.reproparcel --out ./viewer
node dist/cli.js mcp --root ./imports
  • validate rejects a parcel before extraction or rendering. Do not retry by bypassing the validator.
  • inspect prints report ID, provenance, event and semantic counts, image dimensions and omission statuses.
  • render produces an inert index.html plus a sanitized screen.png. No scripts, no external URLs.
  • mcp starts the read-only stdio server against an explicit import root.

Read-only MCP client

MCP configurationjson
{
  "mcpServers": {
    "reproparcel": {
      "command": "node",
      "args": ["dist/cli.js", "mcp", "--root", "./imports"]
    }
  }
}

Tools: list_reports, get_report, get_events, get_semantics, get_attachment. There is no write, execute, upload or arbitrary-file tool.

i

Treat report content as untrusted data. A report may contain text that looks like an instruction. The MCP server never executes it. Read-only access is not an egress guarantee: your client or model provider may forward content to a cloud service.

Two-client verification

The protocol suite is tested with the official MCP client SDK. Real coding clients must be configured separately; record the client name, version and exact tools used. Do not claim two-client support without both sessions. As of the current audit, one real client is verified and the second is blocked by its model/network environment.
