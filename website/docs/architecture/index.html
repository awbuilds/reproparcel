Small modules, one portable contract

ReproParcel is split so a host can adopt only the pieces it needs, while the parcel contract remains independent of Android, the UI and any model provider.

Report lifecycle

  1. The host calls initialize(config) and, when appropriate, setEnabled(true).
  2. The host opens the reporter for a specific surface ID.
  3. The reporter captures the eligible host window before its own window opens.
  4. The runtime returns a captured bitmap or a typed omission.
  5. The user edits and reviews the exact content.
  6. The user may save an encrypted draft.
  7. The user approves the final parcel and chooses a destination.
  8. Export returns FileSaved, ShareLaunched or a typed failure.

The captured bitmap is handed off in process memory, never through a Bundle, Intent extra, navigation argument or saved state. Process death loses the image and the reporter safely starts text-only.

Trust boundaries

Host application

The host is trusted to configure policy, but not to bypass it silently. Every entry point returns a typed outcome. Invalid configuration leaves the runtime uninitialized; disabling cancels SDK-owned work and clears buffers.

Report content

All report text, labels, events and attachments are untrusted data. The viewer escapes text and uses a restrictive CSP. The MCP server returns content as data and never executes instructions from a report.

Desktop import

  • Path allowlist, traversal and absolute-path rejection.
  • Symlink, duplicate and unreferenced-entry rejection.
  • Entry count, compressed/uncompressed size and compression-ratio limits.
  • JSON byte, depth and node budgets.
  • PNG dimension and decoded-byte budgets before rendering.
  • Metadata-stripped PNG re-encoding.

MCP client and model provider

MCP is read-only and accepts report IDs, not arbitrary paths. Read-only access does not prevent the client or its model provider from sending returned content to a cloud service. The MCP responses and integration guide warn about this.

Capture

CaptureController is main-thread gated and requires:

  • a host capture policy with the current surface eligible;
  • an enabled runtime and matching policy generation;
  • a non-secure window (FLAG_SECURE pre-check);
  • a measurable window within the image budget;
  • an attempt token bound to window identity, policy version and layout generation;
  • a bounded 2-second timeout;
  • a post-copy re-check of window, policy, generation and secure state.

Masks are opaque and applied destructively to the sanitized bitmap. The editor starts from that sanitized base; undo cannot restore masked pixels. Raw frames are never persisted.

Drafts

Draft storagetext
noBackupFilesDir/reproparcel/drafts/
  index.json        id, timestamp, encrypted size only
  <id>/report.enc   AES-GCM
  <id>/image.enc    AES-GCM (optional)

The key is Android Keystore-backed AES-256-GCM. Writes are atomic and fsync-ed. Key or crypto failure returns a typed failure; there is no plaintext fallback. Retention defaults to 72 hours, 10 reports and 25 MiB.

Parcel

A .reproparcel file is a bounded ZIP:

Container layouttext
manifest.json
report.json
events.json        optional
semantics.json     optional
attachments/screen.png   optional

The manifest lists every entry with media type, uncompressed size and SHA-256. Checksums detect corruption, not authenticity.

Export

  • SAF CreateDocument is the confirmed local save path.
  • Sharing uses a narrow FileProvider path with a temporary read grant.
  • FileSaved and ShareLaunched are distinct outcomes.
  • A shared file cannot be recalled; the UI states this before approval.
  • Export serialization failure never yields a partial parcel.

Desktop tools

Desktop sourcetext
parcel.ts   streaming bounded ZIP/JSON/PNG validation
viewer.ts   escaped, inert HTML + sanitized image
mcp.ts      stdio server, explicit root, report IDs, five read-only tools
cli.ts      validate / inspect / render / mcp

The desktop implementation shares the schema and synthetic fixtures with the Android writer, not runtime classes.

Error handling

  • Recoverable failures are caught at SDK-owned boundaries.
  • CancellationException is always rethrown.
  • Provider exceptions and timeouts become typed results and cannot crash the host.
  • Privacy failure omits evidence; encryption failure never falls back to plaintext; export failure never produces a misleading partial file.
  • Fatal VM errors, native signals and out-of-memory errors are not swallowed.
