Gated phases, not a promise list

A phase is not complete until its required evidence exists. External gates are recorded as blocked, not silently passed.

Current position

  • Phases 0–5: implemented as the Android/desktop source candidate.
  • Phases 6–9: public reference implementations exist; production and platform gates remain open.
  • Release: none. No tag, GitHub Release, Maven Central publication or deployment exists.
  • Audit: 231 PASS / 43 BLOCKED / 0 UNREVIEWED / 0 IN_PROGRESS.

Local evidence complete

  • Schema v1, bounds, redaction, typed outcomes and parcel checks.
  • Encrypted drafts with key, tamper, quota and TTL tests.
  • Fail-closed capture and opaque masks.
  • Compose reporter, exact preview and approval reset.
  • Offline validator, viewer and read-only MCP.
  • API 26/30/37 emulator and API 31 physical release image export plus desktop import.
  • Startup, capture, memory, collector, trigger-to-composer and paired jank measurements.
  • Public-hygiene scan and final traceability audit.

External or manual gates still open

!

These are blocked, not failed. They require people, devices, accounts or reviews outside the implementation.

  • Five adopter interviews and three concrete use cases.
  • A 20-defect pilot with the PRD threshold.
  • Two external 30-minute integrations.
  • A second real MCP coding client.
  • A current physical device and physical API 26/30 rows.
  • A manual TalkBack matrix and a longer thermal/ANR soak.
  • iOS physical-device, Keychain, scenes and App Store validation.
  • Relay deployment, TLS, backups, source offer and independent review.
  • Legal, Apache-2.0 and trademark review.
  • Sonatype namespace verification, signed Maven Central publication and release approval.

Principles for future work

  1. Privacy and host stability take precedence over collecting more evidence.
  2. No hidden collection, mandatory backend, telemetry or runtime model.
  3. No automatic Compose extraction without a public-API, minified-release compatibility matrix.
  4. No release claim without a green line-level audit and explicit maintainer authorization.
  5. Every new adapter ships with a schema fixture, failure tests and honest limitations.

How to propose a roadmap change

Open an issue describing the user problem, privacy impact, compatibility impact and verification plan. Changes to load-bearing invariants require an architecture decision record and maintainer approval. See GOVERNANCE.md.
