Contributions that keep the contract intact

ReproParcel is maintainer-led and privacy-first. The most useful contributions are small, tested and safe to publish.

i

Read the engineering contract first. The repository's AGENTS.md defines public-repository hygiene, exception boundaries, testing expectations and the handoff protocol. A pull request that ignores it will be asked to change.

Before you start

  • Open an issue describing the problem, the privacy impact and the verification plan.
  • For load-bearing changes — architecture, capture and privacy behavior, storage, export, schema meaning or public API — propose an architecture decision record.
  • Search existing issues and discussions so the same work is not duplicated.

Branch and release model

  • The implementation branch is dev. Pull requests target dev.
  • Do not create, merge into or push main during the pre-release phase.
  • Tags, GitHub Releases, Maven Central publication and deployments require the maintainer's explicit authorization after the release gates pass.

Developer Certificate of Origin

Contributions are accepted under Apache-2.0 and use the Developer Certificate of Origin. Sign off every commit:

Sign-offsh
git commit -s

There is no copyright assignment and no contributor license agreement. A new CLA, license exception or relicense requires an explicit maintainer decision.

Synthetic data only

Never submit real user reports, screenshots, credentials, customer data, private application code or personal information. Use synthetic fixtures with invented shapes. This applies to tests, documentation, screenshots, issues, pull requests, commit messages and handoffs.

!

A suspected leak blocks the change. If in doubt, omit the data. Public-repository hygiene is a gate check, not a style preference.

Engineering expectations

  • Create the smallest failing test before a behavior change.
  • Handle recoverable exceptions at SDK-owned boundaries; always rethrow CancellationException; never write an empty catch or fabricate success.
  • Privacy failure omits evidence; encryption failure never writes plaintext; export failure never yields a partial parcel.
  • Keep dependencies pinned and license-compatible. New dependencies are reviewed before adoption.
  • Run the actual relevant compile, JVM, lint and device checks, and record exact commands and outcomes.
  • Do not claim a check passed if it was not run. Blocked rows stay blocked.

Review

Small changes use lazy consensus in an issue or pull request. A maintainer makes the final decision when consensus is not reached. Review focuses on correctness, privacy, host stability and honest documentation — not on collecting more evidence for its own sake.

Community expectations are in CODE_OF_CONDUCT.md. Report behavior issues through GitHub's moderation tools; report security issues through the private advisory channel.

Documentation contributions

Documentation changes are reviewed like code. If you change behavior, update the compatibility matrix, limits, troubleshooting codes and the changelog in the same change. If you change licensing or release meaning, add an ADR.
